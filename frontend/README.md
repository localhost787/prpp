# PRPP frontend — synthetic local prototype

The active interface is **`apps/dashboard` (Expo / React Native Web)**. The Vite application at this directory's root is a **legacy reference**, not the current dashboard. Their dependency trees and lockfiles are intentionally separate; this is not an npm workspace.

All patient names, clinicians, visits, results and PDF contents in the mock are synthetic examples. Do not enter real patient data or credentials. Client-side permission fixtures are demonstrations, **not authentication or server authorization**. Bundled PDFs can be inspected by anyone with this source; they are not protected clinical records. No real Medplum integration, backend access controls, production readiness, HIPAA compliance or clinical suitability is claimed.

## Active dashboard

Prerequisites: Node compatible with `package.json` (`^22.18.0 || >=24.2.0`), npm, and the two dependency trees. From the repository root:

```sh
cd frontend
npm ci --ignore-scripts
cd apps/dashboard
npm ci --ignore-scripts
EXPO_OFFLINE=1 npm run export:web
# Only if port 3001 is free; do not stop an unrelated process:
python3 -m http.server 3001 --bind 127.0.0.1 --directory dist
```

Open `http://127.0.0.1:3001`, then **Enter example**. `npm run web` is the alternative Metro development command; do not run it and the static server on the same port. These are setup instructions, not a claim that a clean installation was exercised in this snapshot review.

The active web mock includes context/role switching, English and Spanish presentation, Mi visita / My visit, results and six locally bundled synthetic report PDFs (three reports in two languages). Downloads use temporary Blob URLs, not a PDF API endpoint. Results are permission-gated in the UI; those gates do not protect bundled data from source inspection.

My care is integrated in the local mock: care participants and current instructions require the explicit visit permission; medicines have a separate permission. Unknown clinical fields remain unknown. More → Services opens a general fictional directory with distances from an example origin, not GPS or the user's location. Unknown waiting times and plan acceptance are not inferred. Family remains pending. Native iOS/Android, Expo Go, real login, server integration and clinical authorization have not been validated here.

## Tests and tool prerequisites

From `frontend`:

```sh
npm test
mkdir -p docs/evidence/reports-pdf
cd apps/dashboard
npm test
```

The dashboard test command is not pure unit testing: it also launches Chromium and uses Poppler `pdftotext`. It resolves Playwright from the root dependency tree. Its default Chrome executable is `/usr/bin/google-chrome`; override with `REPORTS_CHROMIUM_PATH=/absolute/path/to/chrome npm test`. Ensure that executable and `pdftotext` exist first. The evidence directory must exist before the browser-download test runs. Tests generate local, ignored evidence.

Additional browser scripts under `apps/dashboard/tests` expect the static dashboard at port 3001 and an installed Chrome channel. Run them from `apps/dashboard`. Some assume their output directories already exist; for the general dashboard script, create `../../docs/evidence/dashboard-expo` first. These scripts are preserved developer checks, not a portable CI guarantee. `scripts/check-mock.mjs` and `tests/legacy-width.mjs` target the legacy Vite mock, not the active dashboard.

## PDF sources

`apps/dashboard/src/reports/` includes the generator, bundled PDF bytes, manifest, layout verifier and `FONT-LICENSE.txt`. Regeneration requires an existing Python environment with ReportLab and the DejaVu Sans font at `/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf`; it is not an npm dependency. The layout verifier additionally uses Poppler `pdftotext` / `pdftoppm` and expects the six evidence PDFs generated by dashboard tests. No PDF-tool installation or regeneration is implied by the setup commands above.

## Legacy Vite reference

From `frontend`, after installing its dependencies:

```sh
MEDPLUM_USE_MOCK=true npm run dev
# Or build the legacy mock:
MEDPLUM_USE_MOCK=true npm run build
```

Only the exact value `true` selects its synthetic mock. Without it, Vite selects retained real-client code, which can contact external services; that path is not approved or tested as part of this prototype. Do not run it with real credentials. Environment variables exposed to frontend code are public: never put secrets in `MEDPLUM_`, `GOOGLE_` or `RECAPTCHA_` variables. No `.env` files are distributed.
